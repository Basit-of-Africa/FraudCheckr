# FraudCheckr data

`convictions.csv` is FraudCheckr's single source of truth for conviction records. It is generated by
`scripts/build_dataset.py` from the EFCC source tables in `source/` and must not be edited by hand.
To correct a record, fix the source or the build script and rebuild.

```bash
python scripts/build_dataset.py          # rebuild convictions.csv, excluded_rows.csv, QUALITY_REPORT.md
python scripts/build_dataset.py --check  # fail if the committed files differ from a fresh build
```

## Source

| File | Contents |
|---|---|
| `source/efcc_narrative_2020.csv` | EFCC *Narrative of Convictions 2020*, as extracted from the published PDF |
| `source/efcc_narrative_2021_2024_merged.csv` | EFCC narratives for 2023, 2022, 2021, 2020 and 2024, joined into one file with an online merge tool |

The 2020 table inside the merged file is **not used**. The merge tool treated `#` (used in the source
for Naira) as the start of a comment and truncated two rows. The original 2020 file is intact and is
used instead.

## One row per defendant

Each row is one convicted defendant (a person or an organisation) in one case. When the EFCC listed
several defendants in one row, each named defendant gets a record of their own, with the others in
`co_defendants`. Unnamed co-defendants ("& 2 ORS") are counted in `co_defendants`, never invented.

## Fields

| Field | Description |
|---|---|
| `record_id` | Stable ID: `FC{table year}-{EFCC serial}`, plus `-{n}` when one source row named several defendants. Unchanged across rebuilds while the source is unchanged. |
| `name` | Defendant name, upper case, with prefixes such as `FRN V.` removed |
| `aliases` | Other names recorded ("A.K.A."), separated by `;` |
| `defendant_type` | `individual` or `organisation` (by words such as LTD, LIMITED, ENTERPRISES) |
| `co_defendants` | Other defendants in the same source row, separated by `;` |
| `charge_number` | Court charge number, with the spaces introduced by PDF line-wrapping removed |
| `offence` | Offence as recorded |
| `offence_category` | Normalised category (Impersonation, Cybercrime / internet fraud, …). `Other` when the text is too vague to place; `Not stated` when blank |
| `court` | Normalised court label, e.g. `Federal High Court, Ikoyi` |
| `court_as_recorded` | Court exactly as written in the source |
| `court_type` | Federal High Court, State High Court, FCT High Court, Special Offences Court (Lagos), etc.; blank when unclear |
| `court_state` | State (or FCT) where the court sits |
| `judge` | Presiding judge |
| `date_filed` | Date the charge was filed, ISO 8601 |
| `date_of_conviction` | Date of conviction, ISO 8601 (`YYYY-MM` or `YYYY` when only that is known) |
| `conviction_date_precision` | `day`, `month`, `year` or `none` |
| `sentence` | Sentence text exactly as recorded. This is the authoritative description of the sentence. |
| `custodial_months` | Longest custodial term found in the sentence text, in months. Blank when there is none or it could not be read. |
| `community_service` | `yes` / `no` |
| `option_of_fine` | `yes` / `no`: whether the court allowed a fine instead of imprisonment |
| `fine_naira` | Largest Naira fine named in the sentence |
| `restitution` | Restitution ordered, with currency, e.g. `USD 4,000` |
| `forfeiture` | `yes` / `no`: whether property was ordered forfeited or auctioned |
| `efcc_zone` | EFCC zonal directorate that reported the case |
| `source_table` | EFCC table the record comes from |
| `source_serial` | Row serial number (S/N) in that table |
| `quality_flags` | Semicolon-separated notes; see below |

`custodial_months`, `option_of_fine`, `fine_naira`, `restitution` and `forfeiture` are machine-read
from `sentence`. They support statistics; for any individual record, the `sentence` text governs.

## Deliberately excluded

These source columns are **not published**:

- **Nominal complainant**: often names the victim.
- **Correctional facility** and **expected date of release**: locate a person, which serves no
  research purpose and creates safety risks.
- **Investigating section**: internal EFCC unit codes.

## How the source was cleaned

1. **Column shifts repaired.** In one 2024 Enugu block, 506 rows had the offence in the court column
   (`offence_court_columns_swapped`). In one 2024 Ilorin block, 217 rows had a spreadsheet date in the
   court column (`court_column_held_date`).
2. **Courts recovered from charge numbers.** When the court is missing, the charge-number prefix
   (e.g. `FHC/IL` → Federal High Court, Ilorin) is used, but only for prefixes where at least five
   rows with a recorded court agree at least 80% of the time. Generic prefixes such as `CR` are never
   used. These records carry `court_inferred_from_charge_number`.
3. **Dates read per zone.** The EFCC zones compiled their tables differently, and a spreadsheet tool
   later misread some day-first dates (e.g. `08/02/2023`, 8 February) as month-first. Each block of
   rows from one zone is tested separately: its ISO dates are compared with nearby unambiguous dates
   in the same block, and day and month are swapped only where the evidence is clear. The decision
   for every block is listed in `QUALITY_REPORT.md`. Corrected dates carry
   `conviction_date_day_month_corrected`.
4. **Names split and cleaned.** Numbered lists ("(1) A (2) B"), comma, `&` and `AND` separators are
   split only when every part looks like a full name. Aliases are moved to `aliases`.
5. **Duplicates removed.** Rows with the same name, charge number and conviction date are kept once;
   the dropped copies are listed in `excluded_rows.csv`. Same name and charge number with different
   dates are kept and flagged `possible_duplicate`.

## Quality flags

A flag does not mean a record is wrong. It tells a reader what to check. Counts for the current build
are in `QUALITY_REPORT.md`.

| Flag | Meaning |
|---|---|
| `sentence_mentions_acquittal_or_discharge` | Listed as a conviction, but the sentence text mentions an acquittal or discharge. **Review before publishing.** |
| `sentence_names_specific_defendants` | Several defendants were named in one source row and the sentence refers to specific ones ("only the 2nd defendant"). The outcome may differ between them. **Review before publishing.** |
| `possible_duplicate` | Same name and charge number appear more than once with different details |
| `conviction_date_day_month_corrected` | Day and month were swapped back to undo a spreadsheet misreading |
| `date_order_uncertain` | Day/month order could not be established for this block; the table default was used |
| `filed_after_conviction` | Filing date is later than conviction date in the source |
| `conviction_year_outside_table_year` | Conviction year differs from the table year by more than one year |
| `conviction_date_missing` / `conviction_date_unparseable` | No usable conviction date |
| `filed_date_unparseable` | Filing date present but not readable |
| `offence_court_columns_swapped` | Offence was found in the court column and moved |
| `court_column_held_date` / `court_column_held_other_value` | Court column held a date, judge or other value; it was discarded |
| `court_inferred_from_charge_number` | Court derived from the charge-number prefix |
| `court_missing` | No court recorded and none could be inferred |
| `court_type_unclear` | Court recorded, but its type could not be determined (e.g. `FIAT COURT 1, IBADAN`) |
| `offence_missing` | No offence recorded |
| `charge_number_missing` | No charge number recorded |
| `sentence_missing` | No sentence recorded |
| `sentence_not_parsed` | Sentence text present, but no term, fine or restitution could be read from it |
| `sentence_number_conflict` | Words and digits disagree, e.g. `THREE (2) YEARS`; the words were used |
| `multiple_terms_max_used` / `multiple_fines_max_used` | Several terms or fines (often per count); the largest is given |
| `concurrent_total_ignored` | A cumulative total of concurrent terms was ignored |
| `custodial_term_implausible` | A term over 50 years, almost certainly a typo; not used |
| `suspended_sentence` | Sentence was suspended |
| `life_sentence` | Life imprisonment |
| `single_word_name` | Name is a single word, which is weak for identification |
| `name_contains_digits` | Name contains digits, a likely extraction error |
| `numbered_defendant_list` | Defendants were split from a numbered list |
| `multiple_names_unsplit` | Looks like several names, but could not be split safely |
| `unnamed_co_defendants` | Source mentions other, unnamed defendants |

## Record actions

`record_actions.csv` holds editorial decisions about individual records, applied by the API when it
loads the data (it does not change `convictions.csv`):

| Column | Meaning |
|---|---|
| `record_id` | The record concerned |
| `action` | `hide`: not served by the website or API (e.g. under review after a correction request, or acquitted). `note`: served with `note` shown to readers |
| `note` | Text shown with the record (for `note`) |
| `reason` | Why the action was taken (internal) |
| `date` | When it was taken |

The build fails if an action refers to a record ID that no longer exists, so a change in IDs cannot
silently un-hide a record.

## Using this data responsibly

A record shows that the EFCC reported a conviction of someone with this name. It does not by itself
identify a particular person. Before relying on a record about an individual, match the charge number,
court and date with the court registry, and check whether the conviction was later appealed.
